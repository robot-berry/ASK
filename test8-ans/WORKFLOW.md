# test8-ans 工作流

## 1. 核心原则

模型第一次返回的内容仍是基准事实；本地只对独立的展示副本做答案删除：

- `model_output.txt` 保存第一次模型回复原文；
- `provider_response.json` 保存第一次服务端响应；
- `answer.json` 只是成功解析后的 JSON 视图，不改变字段内容；
- 若 Qwen 把 `s` 写成字符串或重复键，本地按原出现顺序无损收集为数组；模型原句不变，并写入 `transport_normalization.json`；
- `display_answer.json` 是展示专用副本，可以删除明确的最终答案片段；
- `answer_redaction.json` 只记录字段路径、规则、删减字符数和原文哈希，不重复泄漏答案；
- 本地校验给出通过/失败和证据，只有展示副本可进入渲染；严格质量评测与出图资格分开；
- 基准评测固定禁用模型修复调用，确保时延和回答质量都来自同一次回复。

单题探索时可显式使用 `--repair`，但修复结果会单独保存为后续 attempt，不能与第一次回复混为同一基准样本。

## 2. 分阶段流程

### 阶段 A：离线准备

1. `doctor` 检查提示词、Schema、模型和时延门槛。
2. `benchmark --dry-run` 只读取冻结 manifest、固定 smoke 子集、声明的题图和 OCR 结果。
3. 本工程只读取上游准备好的题面文字，不执行 OCR；不读取答案 PDF 或待审答案队列，也不把测试数据用于训练、示例或提示词优化回灌。
4. 校验题图 SHA-256，确认 OCR 条目和冻结题图一一对应。

### 阶段 B：单题探针

用 `probe` 只调用 1 题，验证密钥、接口、JSON 格式和真实时延。失败时停止，不扩大调用量。

### 阶段 C：固定 20 题冒烟

`smoke` 使用数据集自带的 `smoke_20.jsonl`，每科每个 Test 组各一题。每题只调用一次模型并保留原始回复。

需要人工集中检查回答和图片时，`sample --limit 50` 会按数学/物理及 Test 组均衡、确定性地抽取 50 题；结果保存原题图片、模型原始回答截图、脱敏五层图、逐题分阶段时延表和三栏总览页。

三栏审核页提供逐题反馈面板：审核结论、严重程度、问题分类和备注。正式审核使用 `review --batch-dir <批次目录>` 在本机回环地址提供页面；每次保存都会写入 `review_feedback.json`、`review_feedback.csv` 和 `review_feedback_summary.json`。浏览器存储和手动 JSON/CSV 导出仅作备用。直接以 `file://` 打开时无法保证反馈进入工程，不用于正式审核。

### 阶段 D：模型晋级门槛

第一版暂定门槛如下，全部可由 `.env` 调整：

- Schema 通过率至少 95%；
- 本地相关性筛查通过率至少 95%；
- 20 秒时延通过率至少 95%；
- 答案脱敏门禁必须 100% 通过；
- 同时满足结构、相关性、答案脱敏与时延的综合通过率至少 95%；
- 请求失败会同时拉低以上通过率；
- 默认时延口径为 `files_ready_with_png`，从题面文字进入本工程开始，到五张 PNG 全部落盘为止；不包含 OCR。

报告同时给出模型调用、工作流和估算端到端时延的 P50、P90、P95、P99 与最大值。`model_only` 可用于单独比较模型，但产品决策建议看端到端口径。

### 阶段 E：298 题完整评测

只有 smoke 的 `benchmark_summary.json` 通过晋级门槛，且模型 ID、学段、数据集 ID 和两份提示词哈希都未变化，才允许启动 `full`。完整评测只使用 `include_in_benchmark=true` 的 298 个去重候选。

### 阶段 F：五层图片渲染

每道题只要模型回复可解析、`l1`～`l5` 每层至少有一条可展示文字，且脱敏后没有明确残留答案，就立即生成图片。句数、字数、字段细节、相关性、脱敏置信度和 20 秒都只作审核/晋级指标，不阻止出图。图片完成时间仍参与 20 秒统计；`render` 也可以汇总任意批次中可展示的结果：

- 每题输出 `l1.png` 至 `l5.png`；
- 宽度固定 800px；
- 高度按内容增长；
- 只读取已经脱敏的 `display_answer.json`；
- 除答案删除外，只增加层级标题、项目符号和自动换行；
- `n` 仅用于 JSON 内部的小问/选项对齐，公开解析图不显示 A/B/C/D、数字题号或运行编号；
- 第五层对外标题使用“基础解析”，内部仍使用 `l5` 字段；
- 每题另存一张模型原始回答截图用于对照；该诊断截图不参与产品 20 秒门禁；
- 公开图片会先把 LaTeX 数学标记转换为 Unicode/可读公式文本；无法识别的控制命令按安全降级移除，禁止 `$`、反斜杠命令和上下标花括号原样进入成品图。原始 LaTeX 仍只保存在内部 JSON 和模型原始回答截图中。

正式设备渲染前仍建议升级为 KaTeX/MathJax 或其他可验证公式排版，并加入渲染回读、字体缺失、超高图片内存和设备最大解码尺寸测试。“长度不限制”在逻辑上可成立，但实际设备通常仍需设置安全上限或分片策略。

## 3. testzip 数据集接入

`D:\robot\Documents\ASK\datasets\testzip_math_physics_300_v1`

原请求中的反斜杠位于下划线之前，实际文件夹名并不包含这些反斜杠。

默认题面文字来源为 test7-OCR 已经完成的 `official_full298_v14_behavioral` 产物。每题读取对应 `question_document.json` 的 `canonical_text`；这是上游输入，不代表本工程负责 OCR。原图路径只用于哈希和追踪，不会上传给文本模型 `qwen-max`。

数据集没有可靠学段信息，因此 benchmark 必须显式传入 `--stage`。当前也没有人工核验的结构化标准答案，所以报告明确设置 `correctness_scored=false`：只能评估格式、输入相关性筛查和时延，不能声称模型解析正确率。

OCR 报告状态、公式是否独立核验和 OCR 输入就绪时延会单独记录。模型回答与 OCR 文本相关，不等于 OCR 与原图一致；两类质量不能合并成一个指标。

## 4. 本地相关性校验

第一版本地校验是确定性的轻量筛查，不额外调用模型，因此不会显著增加时延：

- 从题面抽取中文短语、变量、数字和公式符号锚点；
- 根据方程、函数、几何、速度、电路等显式线索补充少量教材概念锚点；
- 检查五层总文本长度、题面锚点重合、各层覆盖和空泛操作话术；
- 保存匹配锚点和逐层命中数量，便于人工复核误报。

它只能发现明显跑题或模板化回答，不能证明推理正确。后续若要做真正的语义相关性，应准备人工标注样本，校准本地向量模型阈值；如果改用第二个在线模型当裁判，必须把额外时延、费用和裁判偏差单独统计。

## 5. 本地答案脱敏

答案门禁不读取标准答案，也不求解题目。它从题面定位“所求量”，再检查所有可能进入学生页面的模型字段：

- 删除所求符号被直接赋终值或终区间的片段；
- 删除明确的最终选项、方向、判断结论和证明收尾；
- 保留不属于所求量的中间关系，例如求 `A∩B` 时可保留集合 A、B 各自的区间；
- 任一模型句子/字符串字段命中最终答案特征时，直接删除整条句子或清空整个字段，不裁剪分句、不添加本地占位文字，避免残句和答案尾部残留；
- 无法从题面可靠定位所求量时，标记“脱敏置信度待复核”，但不再删掉整套图；
- 脱敏执行后仍有明确答案嫌疑片段时，才阻止出图；该门禁不依赖严格 Schema 通过。

这是确定性启发式门禁，不等于人工答案泄漏审核。后续最好给冻结集补充每小问 `requested_outputs`（所求符号、定性目标、允许保留的参数），用结构化目标替代题面推断。

若只改了本地结构归一化、答案脱敏或渲染规则，可使用 `reprocess-benchmark` 重放整批已保存的 `model_output.txt`；重放过程不会发起模型请求，并将新产物写到独立批次目录，保留原始评测证据。

## 6. 还需要确定的产品指标

在正式选型前，建议明确以下决策：

1. 20 秒指模型完成时间，还是从拍照、OCR 到五层内容可展示的端到端时间；当前默认采用后者。
2. 采用 P95、P99 还是“95% 样本不超过 20 秒”作为服务等级目标，并规定冷启动是否计入。
3. 测试集学段如何确定。不能长期对全部题统一写成高中而不做人工核验。
4. 相关性、事实正确性、课程不超纲、答案泄漏和五层难度差异分别由谁标注、如何判定。
5. 为每个小问补充结构化 `requested_outputs`，并用人工样本测答案门禁的漏检率与误删率。
6. 是否锁定具体模型快照。浮动的 `qwen-max` 别名可能变化，正式对比应记录并优先固定快照。
7. 单题最大输出 Token、并发数、限流、重试与成本预算。并发会提高吞吐，但不一定降低单题延迟。
8. 同一题是否重复调用以测波动。单次结果无法反映尾延迟和回答稳定性。
9. PNG 中公式排版、字号、色彩、留白、超长图分片和设备解码上限的验收标准。
10. 原图、OCR、模型回复和日志的保存期限、脱敏规则与访问权限。
