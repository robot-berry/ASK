# 数理通 — 功能·解析思路设计文档

> 本文档描述数理通「拍照搜题 → 五层解析 → 诊断补课 → 回到原题」完整学习闭环的设计思路，后续将转化为面向客户的营销文档。

---

## 一、核心理念

### 1.1 痛点
传统搜题软件的致命问题：**直接给答案，学生抄完就走，什么都没学会。**

### 1.2 我们的解法
**不给答案，只给思路。** 同一道题，根据学生水平提供五种不同讲法，学生必须自己完成"最后一跃"（最终计算/得出结论），确保是真学会了，而不是抄完了。

### 1.3 理论支撑
- **布鲁姆掌握学习理论（Mastery Learning）**：任何学生只要给予足够的时间和合适的教学方式，都能掌握学习内容。关键在于精确定位"卡在哪里"，然后补齐再前进。
- **最近发展区理论（ZPD）**：每个学生的认知水平不同，解析的详细程度应匹配学生的最近发展区——既不太简单（无聊），也不太难（挫败）。

## 二、五层解析体系

同一道题，五种讲法，难度递减，学生从 L1 开始看，看懂哪层就停在哪层。

### 2.1 L1 学霸——「只问，不指方向」

| 项目 | 说明 |
|------|------|
| 面向 | 学霸/尖子生 |
| 教学手法 | 用 1~3 个精准提问点拨关键，不给出任何方向或步骤 |
| 目标 | 让学霸自己顿悟 |
| 示例 | 「这道题的关键在于 $F_{浮}$ 和 $G$ 的关系，你能想到什么？」 |
| 设计意图 | 学霸不需要被教，只需要被点醒。直接讲步骤反而剥夺了他们的思考乐趣。 |

### 2.2 L2 优秀学生——「只点知识域」

| 项目 | 说明 |
|------|------|
| 面向 | 中上学生 |
| 教学手法 | 点出涉及的知识模块/公式名称，不展开推导 |
| 目标 | 提示用哪些工具，学生自行完成 |
| 示例 | 「本题考查浮力与重力的平衡，用到 $F_{浮}=\rho g V$ 和 $G=mg$。」 |
| 设计意图 | 优秀学生有知识储备，只是没意识到该用哪个知识点。点一下就能自己跑通。 |

### 2.3 L3 中等学生——「点破题眼」

| 项目 | 说明 |
|------|------|
| 面向 | 中等学生 |
| 教学手法 | 直接指出解题的关键突破口，写出核心步骤框架，关键变形给提示但不算到底 |
| 目标 | 帮学生越过那道"坎"，后续自行完成 |
| 示例 | 「突破口：浸没时 $V_{排}=V_{物}$。先列等式 $\rho_{水}gV=\rho_{物}gV$，接下来你能消掉什么？」 |
| 设计意图 | 中等学生卡住的往往是一个关键点（题眼），点破之后就能顺理成章地解下去。 |

### 2.4 L4 中下学生——「给骨架，肉自己长」

| 项目 | 说明 |
|------|------|
| 面向 | 中下学生 |
| 教学手法 | 给出完整解题骨架（分步编号），每步写明做什么，关键计算/代入留空让学生填 |
| 目标 | 学生沿着骨架填空，在填的过程中学会 |
| 示例 | 「① 计算浮力：$F_{浮}=\rho_{水}gV_{物}=\underline{\quad}$；② 计算重力：$G=mg=\underline{\quad}$；③ 比较 $F_{浮}$ 与 $G$ 的关系。」 |
| 设计意图 | 中下学生需要明确的步骤框架，但如果全部替他算完，他什么也学不到。留空填空是最佳平衡点。 |

### 2.5 L5 学渣——「兜底详解，最后一跃仍归学生」

| 项目 | 说明 |
|------|------|
| 面向 | 学困生/基础薄弱学生 |
| 教学手法 | 从最基础概念讲起，手把手逐步推导，每个公式的来源、变形、单位都讲清楚，但最终代入数值/得出结论留给学生 |
| 目标 | 即使是最薄弱的学生，也能跟着走完整个思路，最后一步自己算出来获得成就感 |
| 示例 | 「浮力公式 $F_{浮}=\rho_{液}gV_{排}$，其中 $\rho_{液}$ 是液体密度……浸没意味着物体完全没入液体中，此时 $V_{排}=V_{物}$……把已知量代入，你能算出 $F_{浮}$ 等于多少吗？」 |
| 设计意图 | 兜底但不包办。即使讲到最细，最后一跃仍然留给学生——这是"不被羞辱"和"真学会"的关键。 |

### 2.6 全景对照表

| 层级 | 面向学生 | 教学手法 | 信息量 | 学生自主度 |
|------|----------|----------|--------|------------|
| L1 | 学霸 | 只问，不指方向 | 最少 | 最高 |
| L2 | 优秀学生 | 只点知识域 | 少 | 高 |
| L3 | 中等学生 | 点破题眼 | 中 | 中 |
| L4 | 中下学生 | 给骨架，肉自己长 | 较多 | 较低 |
| L5 | 学渣 | 兜底详解，最后一跃归学生 | 最多 | 低（但最后一跃自己做） |

## 三、诊断补课机制（规划中）

当学生看完 L5 还是摇头（仍然不懂），系统不会直接放弃，而是启动诊断补课闭环。

### 3.1 触发场景
> 学生看完 L5 兜底详解，仍然表示"没看懂"。

### 3.2 第一步：断点诊断

系统基于本题的**知识依赖链**，自动生成 3 道微型诊断题，精确定位学生卡在哪个环节。

**知识依赖链示例**（浮力题）：
```
密度的概念 → 密度公式 ρ=m/V → 重力与质量的关系 G=mg → 浮力公式 F_浮=ρgV → 浮力与重力的平衡
```

诊断题设计原则：
- 每道只考查链条中一个环节
- 题目极简（一步出结果）
- 按链条从后往前测，定位"松了哪块砖"

### 3.3 第二步：自动生成补课清单

根据诊断结果，系统自动生成针对性的补课内容：
- 只补学生不会的那个环节
- 用 L5 级别的讲解方式（最详细）
- 每个知识点配 1~2 道练习题确认掌握

### 3.4 第三步：回到原题

补课完成后，系统自动带学生回到原题，从 L3（点破题眼）层重新开始引导。

**为什么从 L3 而不是 L1 开始？**
- 刚补完基础知识，学生需要"成功体验"来建立信心
- L3 提供足够的引导，让学生能走通，获得成就感
- 这就是"首胜设计"——让学生体验到"我做到了"的快感

## 四、后台提示词架构

### 4.1 三层架构设计

| 层级 | 名称 | 作用 | 是否变化 |
|------|------|------|----------|
| 第一层 | 系统层 | 全局规则、JSON 格式、LaTeX 规范、禁止给答案等硬性规则 | 固定不变 |
| 第二层 | 层级层 | 当前调用的层级变量（L1~L5），决定解析的详细程度和教学手法 | 每次调用注入 |
| 第三层 | 校验层 | 后台质量校验通道，学生不可见，用于检查解析质量 | 自动触发 |

### 4.2 设计优势
- **系统层固定**：保证输出格式稳定，前端可可靠解析
- **层级层可变**：同一道题可灵活切换解析层级，无需重写提示词
- **校验层独立**：质量把控不影响学生体验

## 五、游戏化设计（规划中）

### 5.1 核心理念
**层数 = 游戏化货币**。学生看的解析层级越低（越简单），消耗的"层数"越多。

### 5.2 设计要素

| 要素 | 说明 |
|------|------|
| 首胜设计 | 第一次在某个层级看懂题目，获得"首胜"奖励 |
| 层数货币 | 看更低层级解析需要消耗更多"层数"，鼓励学生先尝试高层级 |
| 考试场景钩子 | 在考试前/考试后推送相关题目，利用考试压力转化为学习动力 |

### 5.3 设计意图
- 不是惩罚差生，而是鼓励尝试
- 看懂 L1 消耗最少，看懂 L5 消耗最多 → 激励学生"往上够一够"
- 首胜设计让每一次"看懂"都有成就感

## 六、设计原则总结

### 6.1 学生侧——「不被羞辱」
- 五个层级不是五个标签，而是五种尊重
- 无论学生水平如何，都能找到适合自己的入口
- 最后一跃永远留给自己 → 不被"喂饭"，不被看扁

### 6.2 家长侧——「看得见的进步」
- 诊断报告让家长看到孩子"卡在哪里"
- 补课记录让家长看到孩子"补了什么"
- 回到原题让家长看到孩子"真的会了"
- 基于布鲁姆掌握学习理论：不是孩子笨，是地基没打好

### 6.3 系统侧——「真思考，换着讲」
- 不给答案，只给思路
- 同一道题五种讲法，总有一种能让学生顿悟
- 诊断 + 补课 + 回到原题 = 完整学习闭环
- 每一步都有数据记录，可追踪、可量化
