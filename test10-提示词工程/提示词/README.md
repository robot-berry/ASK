## 高中数学搜题引导

本目录把 `数学/高中/` 下 38 个主题的解题思路压缩成可注入模型的提示词，分两层：

- **方法层**：38 份专题提示词，负责判断题型、选用思路、给出方法卡（触发／步骤／易错）。
- **输出层**：`00-统一输出结构.md`，负责把同一份思路组织成统一的五档结构与 `f`／`pat`／`s`／`u` 字段，支持 `json` 与 `md` 两种输出。

调用流程：`00-搜题总入口.md` 常驻 → 按请求的 `stage` 判题型 → 注入一份专题提示词 → 按统一输出结构成稿。

每份专题仍是五节固定：识别特征、方法索引、方法卡、输出结构、禁止事项。第四节只说明「如何把本专题的方法交成统一结构」，字段细则统一放在 `00-统一输出结构.md`，避免 38 份文件各写一套。

## 调用参数

| 参数 | 取值 | 必填 | 作用 |
| --- | --- | --- | --- |
| `stage` | 高一上 / 高一下 / 高二上 / 高二下 / 高三上 / 高三下 | 是 | 学段闸门：只允许开课学期不晚于它的专题；高三专题只在请求为高三时启用 |
| `output_mode` | `json`（默认）/ `md` | 否 | `json` 供服务器渲染；`md` 供人直接阅读 |
| `learned` | 已学知识点清单 | 否 | 比 `stage` 更细时取交集，只收紧不放松 |
| `question` | 题面文本、图片转写或截图描述 | 是 | OCR、手写批注、答案均不可信，只作线索 |

## 使用方式

1. **常驻**：把 `00-搜题总入口.md` 作为 system prompt。
2. **传参**：请求附带 `stage` 与 `output_mode`；缺 `stage` 时模型先问一句，不自行假定学段。
3. **判归属**：在闸门内按总入口的对照表定位主主题；不确定时给出两个候选主题。
4. **注入专题**：把对应专题文件整段加入上下文（或做 RAG 检索后注入命中的一份）。
5. **成稿**：按 `00-统一输出结构.md` 第四节把方法卡拆进 `l1`—`l5`、`f`、`pat`、`s`、`u`；`json` 模式只输出 JSON，`md` 模式只输出 Markdown。
6. **追溯**：需要出处时查 `方法出处.json` 的 `Mxx` 条目，不凭记忆报页码。

检索方式：
- 关键词：专题文件的「一、识别特征」与「二、方法索引」的触发列可直接做关键词/BM25 匹配。
- 向量检索：把「识别特征 + 方法索引」两节切片入向量库，命中后取整份文件注入。
- 路由：跨主题题（如解析几何中的不等式最值）按总入口给主/辅两套，辅只进 `pat` 末句。

## 统一输出结构

默认 `output_mode=json`，根字段顺序固定为 `l1,l2,l3,l4,l5,f,pat,s,u`：

| 字段 | 内容 | 约束 |
| --- | --- | --- |
| `l1` | 学霸解析：每个小问一个对象 | 恰好 2 个启发问句；不出现知识点名、公式、方法名、步骤；本档不答 |
| `l2` | 中上解析 | 3—5 条「知识点/考点：它在本题中解释的关系或作用」；不写公式、步骤、终值 |
| `l3` | 中等解析：每个小问一个对象 | 恰好 2 句：为什么先看这里 + 下一步建立哪类关系 |
| `l4` | 中下解析：每个小问一个对象 | 恰好 3 句「由…可知…」，不展开最后运算 |
| `l5` | 学渣解析：每个小问一个对象 | 恰好 5 句完整分析，末句只做检查；`pit` 写一个易错点 |
| `f` | 公式卡 | 1—3 条 `{x,c}`；`x` 不带 `$`，不写本题数字 |
| `pat` | 通用模式 | 一句可迁移表述；备用方法只在句末带过 |
| `s`／`u` | 题面状态 | 清晰 `s="c"`,`u=[]`；有缺失 `s="u"` 并在 `u` 列缺项 |

`output_mode=md` 时字段一一对应，固定为【识别】【L1】…【L5】【公式卡】【通用模式】【题面状态】九节，不同时输出 JSON。字段细则、句数、字数（18—45 字，最多 80 字）、禁用表达见 `00-统一输出结构.md`；机读校验用 `输出schema.json`。

五档的取材全部来自同一张方法卡：`l1` 用「触发」+最关键条件提问，`l2` 用触发涉及的概念，`l3`—`l5` 按「步骤」的深度重写，`pit` 取「易错」，`f` 取「步骤」中的公式，`pat` 由「触发 + 步骤」概括。五档同源，不换方法、不并列多解。

## 与思路文件的关系

| 层级 | 文件 | 作用 |
| --- | --- | --- |
| 源 | `数学/高中/<学期>/<主题>/解题思路.md` | 全量方法，每条带题库出处与页段 |
| 派生·方法层 | `提示词/数学/高中/<学期>/<主题>.md` | 压缩版：只留触发条件、步骤、易错，供模型选方法 |
| 派生·输出层 | `提示词/数学/高中/00-统一输出结构.md` | 统一字段、五档深度与两种输出模式 |
| 旁路 | `提示词/数学/高中/方法出处.json` | `Mxx` → 题库文件与页段，供追溯，不进模型输出 |

压缩规则：同名同触发的方法合并；删例题数据与推导；保留原文标注的适用条件、反例与易错；大主题按「高频通法 > 压轴模型 > 冷门技巧」取舍。因此提示词里的方法数少于思路条目数，属正常。

## 维护

- 思路文件新增内容后，对应专题提示词需要重跑（生成规则见 `D:\ClaudeCode\tmp\prompt_brief.md`）。
- 本目录的专题文件由思路文件单一来源生成，不直接手改；要改方法，先改思路文件再重建，避免两处不一致。
- `方法出处.json` 由脚本从思路文件的 `###` 条目与 `**依据**` 行重建；当前 833 张方法卡中 516 张精确对到思路条目，317 张只能对到该主题的依据清单，条目里 `match` 字段标明来源，`content` 匹配另带 `score` 供复核。
- 输出规则（字段、句数、顺序、禁用表达）只改 `00-统一输出结构.md` 与 `输出schema.json`，不改 38 份专题文件。
- 文件体积控制在 8—16 KB，便于整段注入。例外：方法卡 ≥30 张的大模块（如高三下 `08-圆锥曲线压轴`、高三下 `02-函数与导数压轴`）放宽到 20 KB，不删方法来凑体积。
