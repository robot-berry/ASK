## 0. 项目工作流程（执行入口）

本文件同时定义三条互相隔离但在发布门禁汇合的流程：日常 OCR 产品流、Gold/基准评测流、真实自建数据流。任何版本都必须完整执行相应流程，不允许开发完成后直接凭少量样例发布。

### 0.0 当前不是停留在 Gold 制作阶段

当前主 OCR、结构组装、题内图片直裁、排版、成品复检、CLI、批处理和产品网页都已经可运行。Gold、自建数据和人工验收属于工程的测试/放行层，不是 OCR 本体，也不会出现在单张图片的正常处理路径中。

```text
日常产品路径（用户直接使用）
  /ocr/ 上传原题
    → 本机结构化 OCR
    → 文字/公式/选项/视觉块组装
    → 题内图片从当前原图直接裁切
    → 800 px 动态排版
    → LaTeX、语义、手写、截断和尺寸轻量门禁
    → 返回成图但保持下载锁定
    → 后台独立回读最终 PNG 并核对输入/输出哈希
    → 最终 PASS 后服务端开放下载；否则显示诊断

后台迭代路径（开发与质检）
  Gold + 冻结测试集 + 真实自建数据
    → 全量/定向回归
    → 人工只验收发生变化或尚无有效结论的最终 PNG
    → 指标达标后晋升版本

真实数据补齐路径（当前未完成）
  采集原稿/手机照片/手写遮挡/多题整页
    → 隐私与许可确认
    → 题界、原稿配对和手写像素 Mask 双审
    → 冻结后只进入评测集，不直接污染 Gold 或产品结果
```

工程现在位于“正式 OCR 主链路与产品入口完成、来源派生 300 题机器门禁通过、真实分布性能和放行证据未完成”阶段。不是停留在制作 Gold：`/ocr/` 已能实际处理任意新题图；Gold 页面只是验证层。继续迭代分成两类：工程内部先优化真实拍照识别时延和可安全恢复的 REVIEW/REJECT；外部数据侧补齐 410 张真实采集、100 张手写 Mask 双审和可发布 PNG 的人工签核。这些缺口限制 `v1.0` 的泛化声明，但不妨碍现在用产品页处理新图片并收集失败样本。

自建数据隔离区不是日常 OCR 运行依赖，也不是让用户先制作 Gold 才能使用产品。若目标只是本机处理新题图，可以暂不进入该入口；只有要训练/调参、证明手机拍照与手写泛化能力，或发布带质量承诺的 `v1.0` 时，它才是防止训练数据、测试答案、人工结论和线上结果相互污染的必要发布设施。

运行 `scripts/run_self_built.ps1` 时默认只输出 Gold、真实采集、手写 Mask、题界、原稿配对、冻结状态和下一条采集任务；需要逐检查器查看完整 JSON 时显式加 `-Detailed`。`-RequireVerified` 是发布前严格冻结门禁，缺少真实图片或双审结论时按设计失败，不能把“目录结构检查通过”解释为自建数据已经完成。

### 0.4 工作流修改如何生效

- `WORKFLOW.md` 是持续生效的工程规格，不是只在项目开始时读取一次；
- 每次运行必须记录工作流文件的 SHA-256；工作流发生变化后，下一轮开始前必须重新检查目标、配置、测试集和晋升门槛；
- 已经完成的旧运行不会被自动改写，仍保留当时使用的工作流哈希；
- 如果修改影响输出格式、评价方法、阈值或数据角色，必须生成新的候选版本并重跑相关历史基线；
- 如果只修正文案且不改变行为，可记录为文档补丁，不强制重跑模型；
- 任何代码实现与当前工作流冲突时，以当前工作流为准，代码必须修正或明确提交变更提案。

## 1. 项目边界

首个可用版本优先支持：

- 初高中数学、物理的单题与单栏试卷；
- 中文、英文、数字、常见数学/物理公式及单位；
- 题号、题干、选项、插图和答题区；
- 透视、旋转、阴影、轻度模糊等拍照问题；
- 复杂几何图、受力图和表格以原图裁块保留；
- 所有低置信度内容可追溯到原图并进入人工复核。

首版不承诺：

- 恢复被手写完全遮挡的印刷内容；
- 将复杂几何图、化学结构式或电路图重新绘制；
- 在没有真实业务测试集的情况下达到商业产品准确率。

### 最终交付目标

在题库未命中的情况下，对初高中数学、物理的单题或试卷照片进行端到端处理：在指定硬件与规定输入规格下，以 P95 不超过 5 秒的时延，完整提取印刷文字、公式、题号、选项、表格及几何图、受力图等视觉内容，输出可追溯的结构化题目和确定性排版结果。主交付图必须是宽度精确为 800 px、高度按内容自动增长的 PNG；系统必须阻止学生手写答案、批改符号和 LaTeX 源码进入成品，自动发现语义遗漏、无依据新增、图片截断、公式渲染失败和关键字符变化。不能可靠确认的内容必须进入人工复核或拒绝输出，不得以猜测结果静默通过。

### 初始量化验收目标

以下是首个可交付版本的门槛，而不是当前完成度；完成数据标注和基线测量后可提高门槛。任何下调都必须记录原因、影响范围和批准人，不得为了让候选版本过线而临时修改。

## 2. 不可违反的原则

1. **原始数据不可修改**：`data/raw/` 中的文件只读保存，所有处理结果写入运行目录。
2. **识别与排版解耦**：模型只输出结构化 JSON，排版器只消费 JSON。
3. **保留视觉证据**：每个文字、公式和图片块必须保存原始坐标及裁块。
4. **不得静默猜测**：无法可靠恢复的数字、运算符、单位和上下标必须标记警告。
5. **测试集长期冻结**：不得使用冻结测试集训练、调阈值或修改提示词。
6. **先测量再优化**：每次改动都要生成新运行记录，并与当前基线比较。
7. **复杂内容保守处理**：不能可靠重建时，保留原图裁块优于生成错误内容。
8. **双向覆盖可核对**：输出必须能回指原图；原图中的有效内容也必须有输出、忽略或复核状态。
9. **可靠性优先于覆盖率**：允许 `REVIEW` 和 `REJECT`，不得为了提高自动通过率而隐藏不确定性。
10. **成品也要复检**：结构化结果正确不代表最终图片正确，必须对实际导出的 PNG 再做检查。
11. **题内图片禁止重绘**：几何图、受力图、电路图、函数图、表格和其他插图必须从原题像素直接裁切并等比缩放；只能做方向纠正、灰度化、白边整理和尺寸缩放，不得用 SVG、绘图代码或生成模型重建。裁框触边、标签不全、含手写或来源不确定时必须进入 `REVIEW`。

## 4. 单页处理流水线

### Stage 0：导入与登记

输入：JPG、PNG 或 PDF 页面。

处理：

- 计算 SHA-256 和感知哈希，检测重复图片；
- 读取尺寸、方向和来源；
- 分配稳定的 `sample_id`；
- 将数据来源、许可证和允许用途写入 manifest。

输出：`manifest.jsonl`。

### Stage 1：图像预处理

同时生成并保留：

- `raw`：原始图；
- `rectified`：旋转与透视矫正图；
- `enhanced`：去阴影与对比度增强图；
- `clean_candidate`：去手写候选图；
- `transform.json`：原图与处理图之间的坐标变换。

禁止覆盖原图。OCR 应同时尝试 `rectified` 和 `clean_candidate`，而不是只使用擦除后的图片。

### Stage 2：版面和题块检测

基础类别：

```text
question_number, subquestion_number, stem, option,
formula, figure, table, answer_blank, score,
header_footer, handwriting, correction_mark
```

每个区域输出多边形、类别、置信度和来源模型。题块归属需要结合栏位置、缩进、题号模式、选项模式和空间距离，不能只按纵坐标排序。

### Stage 3：内容识别路由

| 区域 | 默认策略 | 失败回退 |
|---|---|---|
| 普通文字 | PaddleOCR | 原图/增强图双路识别后择优 |
| 数学公式 | 专用公式识别模型 | 保留公式裁块并标记复核 |
| 简单表格 | 表格结构识别 | 整体保留为图片 |
| 几何图/电路图 | 原图裁块 | 只做背景增强，不生成内容 |
| 手写区 | 屏蔽或单独识别 | 不混入印刷题干 |

视觉语言模型只能用于阅读顺序判断、候选重排和结构补全；不得在没有视觉证据时自由生成关键题目内容。

### Stage 4：结构组装

统一输出 `QuestionDocument` JSON：

```json
{
  "schema_version": "1.0",
  "sample_id": "sample-000001",
  "questions": [
    {
      "number": "12",
      "source_bbox": [120, 340, 1830, 1160],
      "blocks": [
        {
          "type": "paragraph",
          "runs": [
            {"type": "text", "value": "已知函数", "confidence": 0.99},
            {"type": "math", "latex": "f(x)=x^2-2x", "confidence": 0.95}
          ]
        },
        {"type": "figure", "asset": "assets/q12-figure-1.png"},
        {"type": "answer_area", "height_mm": 25}
      ],
      "confidence": 0.95,
      "warnings": []
    }
  ]
}
```

所有文本和公式 run 都应包含 `source_bbox`、`source_image`、`engine` 和 `confidence` 字段；上例为便于阅读的缩略形式。每个输出块必须引用来源区域，所有有意义的来源区域必须在覆盖台账中标记为 `emitted`、`ignored_with_reason` 或 `review_required`，用来同时发现遗漏与无依据新增。

### Stage 5：确定性排版

- 使用 HTML/CSS 构建题目布局；
- 使用 KaTeX 渲染 LaTeX；
- 使用 SVG 绘制简单横线、括号和答题框；
- 主输出使用浏览器整页渲染为 PNG，总画布宽度必须精确为 800 px；
- PNG 高度不设固定值，按内容真实高度加底部安全留白自动增长，不得用固定画布裁切；
- 以页面 `scrollHeight` 或内容边界计算最终高度，使用 full-page 截图或等价实现；
- 图表和公式必须在内容宽度内等比缩放，禁止截掉箭头、坐标轴、刻度、单位、标签或图注；
- 普通 OCR 物理换行应先恢复为连续段落，再按最终 704 px 内容宽度自然换行；分问、章节标题和可靠 A–D 选项边界继续强制断行；
- 短选项只有在标签构成连续 A–D 前缀、标签唯一、内容非空且每项能完整容纳时才可排成最多两列；异常选项结构、长选项或会拆公式的选项保持整题/单列安全排版；
- 超过单张浏览器截图高度上限时，分片无损渲染后纵向拼接，最终仍保持 800 px 宽；
- PDF 是按需生成的次级输出，可使用 A4 分页，但不得反过来限制 PNG 高度；
- 字体、字号、间距和分页由版本化模板控制。

排版阶段不得改变题目文本或数学表达式。

仅修改模板时应使用 `rerender` 从已冻结的来源运行生成新 `run_id`：重新验证来源报告、结构化文档、原图和现有裁图哈希，并从当前原图重裁视觉资产。纯排版运行必须标记 `render_only`，不得计入 OCR 5 秒 SLA、准确率或网页默认候选资格。

对应配置契约：

```yaml
render:
  primary_png:
    width_px: 800
    height_mode: auto
    full_page: true
    bottom_safe_padding_px: 32
    overflow_policy: review
```

### Stage 6：自动验证

对最终排版图再次执行 OCR，并与排版前的结构化内容比较：

- 覆盖台账是否完整，是否存在原图有效区域遗漏或无来源输出；
- 文字归一化后字符差异；
- 数字、正负号、等号、不等号和单位；
- 分数、根号、上下标和角度符号；
- 每个公式是否可解析、可渲染，规范化 token 是否一致；
- 成品中是否出现 `$`、`\\frac`、`\\begin` 等未渲染 LaTeX 源码或非白名单命令；
- 浏览器截图前必须扫描 KaTeX 节点之外的可见文本；残留反斜杠或 `$` 时直接触发安全回退，不能因为样本已是 `REJECT` 就跳过；
- 题号、选项编号及选项数量；
- 插图和表格是否遗漏、误合并、误拆分或截断；
- 几何图、受力图中的箭头、坐标轴、刻度、单位、标签和图注是否完整；
- 裁块边缘是否仍有笔画触边；触边时自动扩大安全边距，无法扩大则进入 `REVIEW`；
- 所有保留的图片裁块及最终 PNG 是否仍含学生手写答案、圈画、批改勾叉或批注；
- 是否出现内容重复、跨题串联、溢出、遮挡或异常空白；
- 最终 PNG 宽度是否恰好为 800 px，高度是否完整覆盖末尾内容及底部安全留白；
- 对最终 PNG 回读 OCR/公式检测的结果是否与 `QuestionDocument` 一致。

延期 PNG 复读只在首轮出现选项标签缺失时追加固定 1.5 倍彩色重试；若仍缺标签，再对同一不可变 PNG 的无损灰度派生图追加一次独立像素复读。报告必须保留三次尝试的变体、尺度、标签与覆盖率证据；只有三次都缺标签才硬拒绝，灰度派生图不得保存为或替换最终成品。仅由旧复读问题造成的拒绝可以再次复读，其他硬拒绝不得借此放宽。

验证输出分三级：

- `PASS`：通过自动门禁，可进入最终人工成品验收；尚不能单独进入正式发布；
- `REVIEW`：可以预览，但必须人工确认；
- `REJECT`：禁止作为最终重排结果。

### Stage 7：人工成品验收

自动验证完成后，复核页面必须加载同一 `run_id` 下实际落盘的 `output.png`，与原题图片并排展示。不得用候选转写、LaTeX 源码、结构化 JSON 或临时 HTML 冒充最终结果。人工逐项检查语义完整、公式视觉结果、源码泄漏、手写残留、原图裁图政策、图像边界、相邻题/噪声、版面截断、填空线/单位/标点及清晰度。

人工验收记录必须与 OCR Gold 分开保存，并绑定 `run_id`、`sample_id`、原图 SHA-256 和成品 SHA-256：

- `PASS`：全部问题项均被人工明确判定为不存在；
- `FAIL`：至少一项问题被明确标出并可附备注；
- `pending`：存在未检查项，不能晋升或发布。

复核界面必须以实际查看能力为先：原图和最终 PNG 均提供原始尺寸放大与 50%–300% 缩放，右侧实时显示已检查项数和问题数；自动状态、人工状态及发布门禁使用独立中文标识。原图或最终 PNG 未成功加载时禁止提交最终结论。保存操作区固定可见，防止长表单中漏保存；`Ctrl+Enter` 保存并进入下一题，切题前对未保存修改进行确认。当前 `run_id` 与 `sample_id` 必须同步到网址，支持直接收藏和发送具体题目的复核链接。同题旧运行的人工记录只有在旧运行身份、来源哈希、成品报告关联和记录结构均通过服务端校验后才有效。若当前原图哈希一致，且当前 PNG 与旧成品解码成统一 RGB 后尺寸及每个显示像素完全一致，可以只读沿用原人工 PASS/FAIL，不复制或改写旧记录，也禁止重复提交；文件压缩方式和 PNG 元数据差异不算成品变化。只要任一显示像素变化，就必须恢复为当前运行的 `pending` 并重新验收。自动状态不是人工结论：自动未通过时，即使人工标为 PASS，也只能保留审计记录，不能进入发布目录。

正式发布采用双层门禁：流水线必须先为无问题的自动 `PASS`，同一成品还必须具有哈希匹配的人工 `PASS`。两者缺一不可；人工结论不得覆盖公式核验、手写拒绝、原图直接裁图、800 px、回读或来源台账等自动门禁。发布包复制该题的 `human_output_review.json` 作为审计证据。运行级人工结果可导出 CSV，至少包含流水线状态、人工结论、问题码、复核人、时延、真实图片尺寸和输入/输出 SHA-256。

Gold 制作页只负责建立评测真值。候选预标注默认显示不含 LaTeX 命令的可读预览，采用候选时由服务端统一拆出题号、题干和普通选项行，标注人员不直接编辑 JSON；规范转写通过离线 KaTeX 进行视觉预览，原始公式源码仅在主动编辑时展开。公式预览有解析错误、选择题缺少至少两个完整选项或选项标签重复时不得晋升 Gold。该页面不参与成品 PASS/FAIL 判定。

置信度阈值必须通过验证集校准，不能凭经验硬编码后长期不变。

```text
正式来源派生 OCR 评测：gaokao_physics_300_v1_0_1 的冻结 300 题
        ↓
真实拍照/手写安全回归：testzip_math_physics_300_v1（不计算正式 OCR 准确率）
        ↓
非金标兼容性回归：eink2k v439 中 1982 条 benchmark_eligible 记录
        ↓
真实拍照外部回归：MathVision-Wild 冻结部分
```

四组结果必须分别报告，不合并成一个无法解释的“总体准确率”。数学与物理、初中与高中、干净渲染与真实拍照、RGB 与四级灰阶也必须分桶报告。

#### 重复与非数据文件处理

- `testzip_math_physics_2000_v3_eink` 的 300 个 `seed_v2` 样本与 `testzip_math_physics_300_v2_eink` 同源，跨集合比较时按 lineage 去重；
- `Test.zip` 和 `初中.zip` 等压缩包是来源或发布包，不作为第二份输入再次扫描；
- 优先读取 manifest 指定的图片，不允许对 `datasets` 根目录递归抓取所有 PNG；
- `数学提示词.docx` 是参考文档，不是样本；`~$数学提示词.docx` 是临时锁文件，两者均排除；
- `answers/`、`gold/`、答案 PDF、review queue 和报告文件均属于隔离评测面，不属于模型输入面；
- 如果将任一测试集改作开发或调参用途，必须修改其登记角色，并另外建立未接触的新冻结测试集。

### 当前数据缺口

上述本机数据显著增强了中文、数学、物理和电子纸场景的评测，但仍不能覆盖：

- 同一试卷“干净原稿—带学生手写照片”的成对数据；
- 手写、印刷字和批改符号的像素级掩膜；
- 手机斜拍、阴影、折痕、模糊等中文真实拍照分布；
- 多题整页及双栏版面的题目边界金标；
- 每道电子纸题的规范题干、选项和公式转写金标。

这些缺口不能全部由一个公开数据集解决。公开数据可用于预训练、建立模块基线和外部回归，但不能用答案 Gold 替代 OCR Gold，也不能把别的数据集的文字当成本机图片的转写真值。

### 外部数据接入顺序

1. **先登记，不下载**：在 `configs/datasets.yaml` 记录主页、申请状态、许可、版本、预计大小、用途和禁止用途；
2. **许可闸门**：`license_status` 不是 `approved` 时，禁止下载、训练和再分发；代码开源不能推导出数据也可商用；
3. **按价值与体积排序**：先接入约 1.55 GB 的 OmniDocBench 和公式模块需要的 UniMER-Test；SCUT-EnsExam 获批后接入；M6Doc 只抽取数学/物理相关的 test paper、textbook、note 和 photographed 子集；DocLayNet 首期不下载；
4. **固定版本**：保存上游版本号或 commit、文件清单、SHA-256、官方划分和下载日期；OmniDocBench 等持续更新的数据不得直接跟随 `main` 漂移；
5. **隔离用途**：训练、验证和冻结测试使用不同来源清单；`evaluation_only=true` 的样本永远不能进入提示词、检索、训练或阈值校准；
6. **按文档来源去重**：同时做文件哈希、感知哈希、文字指纹和来源 lineage 去重，防止相同 PDF 页面跨数据集泄漏；
7. **转换但不覆盖**：原始下载只读保存，统一格式写入派生目录，并保留原始 ID 到项目 `sample_id` 的映射；
8. **空间控制**：默认只下载所需 split/子集；可流式读取时不复制全量；原始压缩包完成哈希校验和解压验证后可转入远端冷存储。

### 必须继续自建的最小金标层

接入公开数据后仍需建立下列本项目金标，完成前不得宣称五类缺口已经关闭：

- `eink_ocr_gold`：直接标注本机 `benchmark_eligible` 电子纸题的题干、选项、公式 LaTeX、单位、图表引用和忽略区域；先做双人复核的分层子集，再逐步扩到全量；
- `question_boundary_gold`：在中文多题单栏/双栏/跨页试卷上标注题界、小题归属、选项归属和阅读顺序；
- `handwriting_mask_gold`：像素级区分印刷内容、学生手写、批改符号及重叠/不可恢复区；
- `zh_photo_pairs`：同一原稿在不同手机、角度、光照、阴影、折痕和模糊条件下的照片，并保留干净数字原稿；

## 7. 每个版本内部的单轮运行流程

第 0.2 节定义版本从需求到发布的完整闭环；本节定义一个版本内部每次实验或修复怎样运行。每轮使用唯一编号，例如 `2026-09-04-r001`。

```text
确定本轮目标
  ↓
锁定代码、配置、模型和数据版本
  ↓
运行 val 与外部开发集
  ↓
按失败类型聚类并抽样人工检查
  ↓
只修改一个主要变量
  ↓
重新运行完整回归
  ↓
与当前基线比较
  ↓
晋升为新基线或拒绝本轮改动
```

每轮必须记录：

- Git commit；
- 配置文件哈希；
- 模型名称与权重哈希；
- 数据清单版本；
- 环境与硬件；
- 总耗时和单页延迟；
- 总体指标及各场景指标；
- 新增失败、修复失败和遗留失败；
- 是否晋升为基线以及原因。

## 8. 失败分类

| 代码 | 类型 | 示例 |
|---|---|---|
| `PRE-ROTATE` | 方向错误 | 页面旋转 90 度后未纠正 |
| `PRE-WARP` | 透视/弯曲 | 行文字仍明显弯曲 |
| `INK-FP` | 手写误检 | 印刷负号被当作手写擦除 |
| `INK-FN` | 手写漏检 | 学生答案进入题干 |
| `LAYOUT-SPLIT` | 题目误切分 | 一题被拆成两题 |
| `LAYOUT-MERGE` | 题目误合并 | 相邻两题被合并 |
| `OCR-TEXT` | 普通文字错误 | 汉字或英文识别错误 |
| `OCR-CRITICAL` | 关键符号错误 | 数字、单位、正负号错误 |
| `MATH-DETECT` | 公式漏检 | 行内公式当成普通文字 |
| `MATH-RECOG` | 公式识别错误 | 指数、分数、根号错误 |
| `ASSET-MISSING` | 图表遗漏 | 几何图未进入重排结果 |
| `ASSET-CLIP` | 图表截断 | 箭头、坐标轴、标签或图注被裁掉 |
| `HANDWRITING-OUTPUT` | 手写污染成品 | 学生答案或批改符号进入题干、选项或保留图片 |
| `LATEX-LEAK` | LaTeX 泄漏 | 成品出现未渲染的公式源码 |
| `SOURCE-OMISSION` | 来源内容遗漏 | 原图有效区域没有输出或复核记录 |
| `UNSUPPORTED-OUTPUT` | 无依据新增 | 输出内容无法回指任何原图区域 |
| `ORDER` | 阅读顺序错误 | 双栏内容串行 |
| `RENDER` | 排版错误 | 溢出、遮挡或分页异常 |
| `RENDER-SIZE` | 成品尺寸错误 | PNG 不是 800 px 宽或底部被截断 |
| `VERIFY-MISS` | 验证漏报 | 成品有错误但被判为 PASS |

修复失败时，将样本 ID 加入对应回归集合；除非确认标注错误，否则不得从回归集删除。

## 9. 核心指标

### 识别层

- 文本 CER/WER；
- 关键 token 准确率：数字、运算符、单位和选项标记；
- 公式规范化完全匹配率；
- 公式可解析率、可渲染率、规范化完全匹配率及渲染视觉一致性；
- LaTeX 源码泄漏率和非白名单命令命中率；
- 手写分割像素 F1、手写漏检率与印刷内容误删率；
- 红笔批改、圈画、勾叉和与印刷内容重叠手写的分桶指标。

### 结构层

- 题目起止边界 F1；
- 题号与小题号准确率；
- 选项数量和归属准确率；
- 阅读顺序准确率；
- 图表召回率；
- 图表完整裁切率、边缘触笔率、误合并率和误拆分率；
- 来源区域覆盖率与输出块来源映射率。

### 端到端层

- 整题零错误率；
- 自动 `PASS` 的准确率；
- 自动 `PASS` 覆盖率；
- 需要人工修改的比例；
- 严重静默错误率；
- 成品中手写污染率、LaTeX 泄漏率和视觉内容截断率；
- 800 px 宽度合规率，以及溢出、遮挡、底部截断率；
- 单题和整页分别统计 P50/P95/P99 延迟及超时率；
- 冷启动与热启动、CPU 与 GPU 分开统计；
- 每页失败率、崩溃率和批处理成功完成率。

5 秒交互指标必须是端到端时间，至少包含输入读取、预处理、版面分析、文字与公式识别、图表裁切、结构组装、800 px PNG 渲染、在线成品边界/尺寸/源码安全检查和文件写入。耗时更高的独立 PNG OCR 回读允许作为第二阶段异步运行，但第一阶段必须明确返回 `REVIEW`，不能先显示为已验证或进入发布目录；回读完成后要核对原图及成品哈希、原子更新状态，并单独记录耗时。正式发布门禁仍要求独立回读通过。验收报告必须同时报告“交互可用时间”和“发布就绪时间”，不得用异步化掩盖总计算成本。建议首个基准桶使用单题、1280×720 输入、并发 1，其他分辨率和整页试卷另行报告。

正式性能批次必须独占约定的 GPU/模型服务环境。运行前及运行中要探测配置列出的本机冲突服务；检测到响应时默认中止，不加载新模型或继续生成可误认为正式候选的结果。诊断需要时可以显式允许冲突，但运行报告必须写入 `ALLOWED_CONFLICT`，该运行不得成为默认复核版本、性能基线或发布候选。资源冲突中止与坏样本失败分开统计，已完成样本可保留用于定位，但不算完整批次。

不得只用平均字符准确率决定是否发布。

## 10. 版本晋升门槛

候选版本只有同时满足以下条件才能成为新基线：

1. 冻结测试集的整题零错误率不下降；
2. 关键 token 指标不下降；
3. 没有新增已知严重静默错误；
4. 自动 `PASS` 样本抽检达到项目设定的可靠性目标；
5. 所有历史 P0/P1 回归样本通过；
6. 自动 `PASS` 关键内容正确率、严重静默错误、手写污染、LaTeX 泄漏和图表截断达到第 1 节的量化门槛；
7. 最终 PNG 全部精确为 800 px 宽，且没有溢出、遮挡或底部截断；
8. 指定硬件和基准输入桶的端到端 P95 不超过 5 秒，冷启动数据单独提供；
9. 性能运行的资源冲突探测为 `CLEAR` 或按版本记录为无冲突的旧基线；不得使用 `ALLOWED_CONFLICT`、`ABORTED` 或不完整运行晋升；
10. 批处理成功完成率不低于 99.5%，单个坏样本不会终止整个批次；
11. 性能和资源消耗没有超出预算；
12. 运行产物完整，可以追溯代码、工作流、配置、模型、数据、字体和渲染器版本。

如果准确率提高但严重静默错误增加，版本不得晋升。

## 11. 结果保存与空间控制

### 保存模式

工程提供三级产物策略，由每次运行的 `artifact_mode` 控制：

| 模式 | 永久保存内容 | 适用场景 |
|---|---|---|
| `minimal` | JSON、指标、报告、失败样本完整图片、成功样本缩略图与抽检样本 | 日常迭代，默认模式 |
| `debug` | 指定样本的全部中间图片和调试信息 | 定位具体错误，不应用于无筛选的全量测试 |
| `release` | 全部最终 PNG/PDF、结构化结果与报告；普通中间图仍不永久保存 | 正式基线、验收和交付 |

默认不得为每次全量回归永久保存每道题的所有中间 PNG。

### 默认配置

后续在 `configs/pipeline.yaml` 中实现以下配置：

```yaml
artifacts:
  mode: minimal
  keep_pass_full_images: false
  pass_sample_ratio: 0.03
  keep_review_images: true
  keep_reject_images: true
  keep_release_final_images: true
  cache_ttl_days: 7
  intermediate_format: webp_lossless
  delivery_format: png
  content_addressed_assets: true
render:
  primary_png:
    width_px: 800
    height_mode: auto
    full_page: true
    bottom_safe_padding_px: 32
    overflow_policy: review
```

`pass_sample_ratio` 使用由 `run_id` 派生的固定随机种子，使相同运行可以复现抽检集合。

### 原始输入规则

- 原始测试图片不复制到运行目录，只保存数据集 ID、`sample_id`、源路径和 SHA-256；
- 运行时必须通过 manifest 解析输入，不能递归复制整个数据集；
- 数据集移动后，只有路径注册表可以更新，样本 ID 和内容哈希不得改变；
- `data/raw/`、本机 `datasets/` 和外部冻结集永远不属于缓存清理范围。

### `minimal` 模式保存规则

对于 `PASS` 样本：

- 保存 `document.json`、`verification.json` 和运行结果索引；
- 保存小尺寸 WebP 缩略图；
- 默认不永久保存 `rectified`、`enhanced`、mask、完整重排 PNG 或 PDF；
- 按固定比例抽取成功样本，保存完整调试产物供人工审计。

对于 `REVIEW` 和 `REJECT` 样本：

- 保存矫正图、增强图、手写 mask、版面覆盖图、区域裁块和最终重排图；
- 保存每阶段 JSON、模型置信度和验证差异；
- 长期保留已经进入回归集的 P0/P1 失败样本。

### 单次运行目录

```text
artifacts/runs/<run_id>/
├─ run.json                    # 代码、工作流、配置、模型与数据版本
├─ metrics.json                # 总体及分桶指标
├─ results.jsonl               # 每个样本的状态和产物引用
├─ failures.jsonl              # REVIEW/REJECT 与失败分类
├─ sampled_pass.jsonl          # 固定抽取的 PASS 审计样本
├─ report.html                 # 可视化报告
├─ thumbnails/                 # 成功样本的小图预览
└─ debug-samples/
   └─ <sample_id>/             # 失败样本和抽检样本的完整产物
      ├─ input.json
      ├─ rectified.webp
      ├─ enhanced.webp
      ├─ handwriting-mask.webp
      ├─ layout.json
      ├─ crops/
      ├─ recognized.json
      ├─ document.json
      ├─ rendered.html
      ├─ rendered.png
      ├─ verification.json
      └─ debug-overlay.webp
```

每次运行完成后更新：

```text
artifacts/latest.json
artifacts/reports/<run_id>-summary.json
artifacts/reports/<run_id>-report.html
```

`latest.json` 只记录最近一次完整运行的 ID、状态、完成时间和报告路径，不复制报告内容。

### 可重新生成原则

最终重排图由以下内容确定性产生：

```text
document.json
+ 排版模板版本
+ 字体版本及哈希
+ KaTeX/渲染器版本
+ 原图资产引用及裁切坐标
```

以上信息齐全时，日常运行的完整 PNG/PDF 可以删除后重新生成。每次运行必须在 `run.json` 中记录这些版本，避免同一 JSON 在不同环境下产生不可解释的排版差异。

### 图片去重

- 长期图片资产使用 SHA-256 内容寻址，建议路径为 `artifacts/assets/sha256/<前两位>/<完整哈希>.<ext>`；
- 相同内容只保存一次，各运行通过哈希引用，不再复制；
- 原图裁块如果没有经过像素修改，只记录原图哈希和裁切坐标，不单独保存图片；
- 对黑白或少色图先比较优化 PNG 与无损 WebP 的实际大小，不强制把更小的 PNG 转为 WebP；
- 正式交付仍使用 PNG/PDF，内部中间图可使用无损 WebP。

### 缓存和保留周期

- `artifacts/cache/` 中的普通中间图默认保留 7 天；
- 日常运行的 JSON、指标、失败清单和报告长期保留；
- 非回归用途的完整 PASS 图片在缓存过期后删除；
- `REVIEW`、`REJECT` 和历史 P0/P1 回归样本长期保留；
- `artifacts/releases/` 和 `artifacts/baselines/` 永不由自动清理任务删除；
- 清理程序只允许操作解析后仍位于 `artifacts/cache/` 内的路径，并在删除前输出 dry-run 清单和清理报告。

### 正式发布目录

只有晋升为基线或明确要求交付时才创建完整发布包：

```text
artifacts/releases/<version>/
├─ release.json
├─ metrics.json
├─ report.html
├─ structured/                 # 全部 QuestionDocument JSON
├─ png/                        # 全部最终 PNG
├─ pdf/                        # 按需生成的 PDF
└─ checksums.sha256
```

`png/` 中每张主交付图片必须精确为 800 px 宽，高度按各题内容独立确定。发布包不保存普通预处理中间图；出现问题时应通过 `run_id`、结构化 JSON 和确定性渲染信息复现。

### 空间监控

每轮结束在 `metrics.json` 中记录：

- 本轮新增字节数；
- cache、runs、assets 和 releases 各自占用空间；
- 内容寻址去重节省的空间；
- 预计缓存到期可释放空间；
- 单样本平均产物大小和失败样本平均产物大小。

若本轮预计产物超过配置中的空间预算，应在运行前停止并提示，而不是运行到磁盘耗尽。

### GitHub 与远端归档策略

GitHub 用于工程版本管理和异地备份，不直接承担全量数据仓库职责。仅把文件推送到 GitHub 不会自动释放本地空间；必须在远端上传完成、下载抽查成功且 SHA-256 一致后，才能按保留策略清理可再生成的本地缓存。

| 存储层 | 保存内容 | 规则 |
|---|---|---|
| GitHub 普通 Git 仓库 | 源码、配置、工作流、Schema、数据清单、哈希、少量基线指标和文档 | 默认方案；不提交密钥、原图、完整数据集、模型权重、运行缓存或全量 PNG |
| GitHub Releases | 明确发布版本的小型演示包、校验和及少量代表性成品 | 只用于可交付版本，不保存每轮迭代产物 |
| Git LFS | 必须随版本分发、更新频率较低的较大文件 | 非默认；启用前必须评估配额和费用，同一大文件的新版本会继续消耗存储 |
| 专用对象存储或数据集托管 | 全量发布图片、模型权重、较大评测产物及可共享数据集 | 推荐用于真正的大文件；仓库中只保存远端 URI、SHA-256、大小和访问级别 |
| 本地缓存 | 可重新生成的中间图片与近期调试结果 | 按 TTL 自动清理，不作为唯一副本 |

远端仓库默认先设为私有，确认数据授权、题目版权、学生隐私和密钥扫描均无问题后，才能决定是否公开。`D:\robot\Documents\ASK\datasets` 始终位于工程仓库之外，不得因为初始化仓库或执行批量添加而被提交。

每个远端归档对象必须在 `release.json` 或产物索引中保存：

```json
{
  "artifact_id": "release-v0.1.0-png",
  "remote_uri": "provider://bucket/path/object",
  "sha256": "...",
  "size_bytes": 0,
  "uploaded_at": "ISO-8601",
  "verified_download_at": "ISO-8601",
  "access": "private"
}
```

允许清理本地完整产物必须同时满足：

1. 结构化 JSON、版本信息和资产引用完整；
2. 远端上传已完成，并通过下载抽查与 SHA-256 校验；
3. 目标不属于原始数据、人工标注、当前基线或 P0/P1 回归保留项；
4. 清理只作用于明确解析到 `artifacts/cache/` 或允许清理的非基线运行目录；
5. 清理前生成 dry-run 清单，清理后写入审计日志；
6. 任一条件失败时保留本地文件并报告原因。

仓库应提交 `.gitignore`，并在首次推送前逐项检查暂存清单。禁止使用无法审阅范围的批量提交方式，避免把 `.env`、访问令牌、试题原图、学生信息和大型运行产物写入 Git 历史。

## 12. 逐版本迭代计划

版本采用 `主版本.能力版本.修复版本`：`v0.x.0` 增加一组可验收能力，`v0.x.y` 只修复该能力范围内的问题，`v1.0.0` 表示达到第 1 节全部交付门槛。每个版本内部可以执行多轮 `run_id`，只有通过门槛的一轮才成为该版本基线。第 5 节的 `D0` 是所有能力版本共享的数据前置阶段，不另占软件版本号；未完成人工金标的阶段可以开发功能，但不得据此晋升依赖该金标的准确率目标。
